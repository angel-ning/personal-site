## 0. 核心地图（先建立整体框架）

第 2 周学的 classful 地址只有两段：**N + H = 32**。问题是一个 Class B 网络有 65,534 台主机、全在一个广播域里，太大了；Class C 网络又只能放一个 LAN，公司有好几个 LAN 就不够用。这周的办法是：**从 host 部分借几位出来，当作「子网号」**。

```
为什么：一个大网络 → 切成多个小网络（subnet），控制广播、提高性能、便于管理和隔离
   → 怎么切：从 host 最左边借 n 位 → N + S + H = 32（板书第一页）
   → 怎么告诉设备切在哪：Subnet mask（N、S 位写 1，H 位写 0）→ 255.255.255.224 = /27
   → 能切几个、每个多大：子网数 = 2ⁿ（n = 借的位数），每个子网主机数 = 2ʰ − 2（h = 剩下的 host 位）
   → 列子网表：每个子网的 Network address（h 全 0）· Host range · Broadcast address（h 全 1）
   → 按需求规划：先看要几个子网（定最少借几位），再看每个子网要几台主机（定最多借几位）
   → 路由器怎么判断：目的 IP AND 子网掩码 = 子网地址 → 查路由表转发
```

**一句话抓住本周**：**子网掩码就是一把尺子，告诉你 32 位里前多少位是「网络 + 子网」**。所有计算题都是同一个套路：**定 Class → 数借了几位 → 写掩码 → 算间隔（256 − 掩码值）→ 一行行列出子网**。

## 1. 🔴 为什么要划分子网（Reasons for Subnetting）

<Figure src="images/page_03.png" caption="SOLUTION: Create another section in the IP address called the subnet —— NETWORK | SUBNET | HOST；Subnet Field 从原来的 host 部分里切出来" source="Slide 3" />

- **To create a subnet address, a network administrator borrows bits from the original host portion and designates them as the subnet field**（Slide 2）
- **Subnetting** is the process of segmenting a network into multiple smaller network spaces called **subnetworks or subnets**（Slide 6）

| 课件原文（Slide 6） | 中文 / 小白解释 |
|---|---|
| **Control traffic by containing broadcast traffic within each subnetwork** | 广播只在子网内部传播，不会淹没整个大网络（路由器不转发广播，第 2 周） |
| **Reduce overall network traffic and improve network performance** | 每个子网里的设备少了，流量小，性能更好 |
| A **router is necessary** for devices on different networks and subnets to communicate | 不同子网之间通信要经过路由器 |
| Each router interface must have an IPv4 host address that **belongs to the network or subnet that the router interface is connected** | 路由器每个接口的 IP 必须属于它连着的那个子网 |
| Devices on a network and subnet use the router interface attached to their LAN as their **default gateway** | 子网里的设备把路由器接口当作默认网关 |

<Figure src="images/page_07.png" caption="Class B：Before Subnetting = NETWORK | HOST；After Subnetting = NETWORK | SUBNET | HOST" source="Slide 7" />

> **Internet knows your network as a whole**, subnet field will become **additional routing bits**, routers **within your organization** can recognize different locations, or subnets, within the whole network.（Slide 7）

<Callout type="tip">

**外面看是一个整体，里面分成好几块**：Internet 上的路由器只知道「130.12.0.0 这个网络在你们公司」，路由表里只要一条；进了公司之后，公司自己的路由器再看子网位，把包送到正确的部门（子网）。就像快递先送到「港科大」，再按楼号送到具体的楼。

</Callout>

<Figure board src="images/BOARD4_TOPOLOGY.png" caption="192.168.10.0（Class C，N.N.N.H）：PC1、PC2 → 路由器 A → B → C → D，每台路由器后面各挂两台 PC；下面写着 Class B –、Class C –" source="M4 Supplementary p.3" />

<Callout type="board" title="老师板书：一个 Class C 网络，要给几个网络编址？（我的解答）">

**先数一共有几个网络**——每个**路由器接口**连一个网络（第 2 周：网络的边界是路由器接口），**两台路由器之间的线也是一个网络**：

| # | 网络 | 在哪 |
|---|---|---|
| 1 | PC1、PC2 所在的 LAN | A 左边 |
| 2 | PC3、PC4 | A 上面 |
| 3 | PC5、PC6 | B 上面 |
| 4 | PC7、PC8 | C 上面 |
| 5 | PC9、PC10 | D 上面 |
| 6 | A–B 之间的线 | |
| 7 | B–C 之间的线 | |
| 8 | C–D 之间的线 | |

一共 **8 个网络**，但只有 **一个** Class C 网络 192.168.10.0。以前（第 2 周）的做法是每个网络用一个 Class C，要 8 个；现在只用 192.168.10.0 一个，**从 host 的 8 位里借 3 位**（2³ = 8 个子网），每个子网剩 5 位 host → 2⁵ − 2 = **30 台主机**，足够。这张图的 8 个子网正是下一页板书那张表（见第 4 节）。

下面的「Class B –」「Class C –」推测是让我们对比：同样的拓扑如果给的是 Class B（例如 130.12.0.0），可以借更多位、每个子网放更多主机（第 4 节板书 p.5、p.6）。

</Callout>

<Figure board src="images/BOARD4_EXAM_SERVER.png" caption="路由器 A 后面：PC1–PC4、exam server、email server 全在同一个网络 192.168.10.0；下面把同样的设备画成以 A 为中心的星形" source="M4 Supplementary p.10" />

<Callout type="board" title="老师板书：exam server 和学生 PC 在同一个网络里（我的解答）">

- **上图**：所有设备都在 192.168.10.0 **一个网络、一个广播域**里。学生的 PC 和 **exam server** 之间**不经过任何路由器**，路由器 A 根本没机会检查它们之间的流量——想用 ACL 禁止学生访问考试服务器也做不到（第 1 周板书讲过 ACL 在路由器上）。任何一台 PC 发的广播，服务器也都得处理。
- **下图（划分子网后）**：A 的每个接口连一个子网，例如 PC1–PC4 在一个子网、exam server 一个、email server 一个。学生访问考试服务器必须**经过 A**，A 就可以用 ACL 控制「谁能访问 exam server、什么时候能访问」；广播也被限制在各自的子网里。
- 这就是 Slide 6 的理由在安全上的体现：**子网 = 在网络里划出边界，边界上的路由器就是检查站**。

</Callout>

<Callout type="extra" title="课外补充：子网划分与安全（network segmentation）">

安全领域叫 **network segmentation（网络分段）**：把服务器、员工电脑、访客 Wi-Fi、IoT 设备放进不同子网（或 VLAN），之间用路由器 / 防火墙控制。好处是**限制攻击横向移动 (lateral movement)**——一台员工电脑中了病毒，也不能直接扫描、攻击数据库服务器所在的子网。PCI DSS 等合规标准也要求把处理信用卡数据的系统隔离在单独的网段里。

</Callout>

## 2. 🔴 借位：N + S + H = 32

<Figure board src="images/BOARD4_INTRO.png" caption="IPv4：N + H = 32 → N + S + H = 32；Class C = N.N.N.hhhhhhhh，借 3 位后 = N.N.N.SSS hhhhh；下面 4 道题：借 3 / 4 / 6 / 10 位，写 Subnet Mask" source="M4 Supplementary p.1" />

- **Host bits must be reassigned (or "borrowed") as network bits**（Slide 4）
- **The starting point is always the leftmost host bit**：永远从 host 部分**最左边**开始借，连续地借
- 借 n 位 → **2ⁿ 个子网**

<Figure src="images/page_04.png" caption="Class C 192.168.10.0：借 3 位 → N.N.N.sN H → 2³ = 8 个子网" source="Slide 4" />

<Figure src="images/page_05.png" caption="Class B 147.10.0.0 借 5 位 → 32 个子网；Class A 28.0.0.0 借 12 位 → 4096 个子网" source="Slide 5" />

| Class | 原来 | Host 位 | 最多能借（Slide 24） | 例子 |
|---|---|---|---|---|
| **A** | N.H.H.H | 24 | **22** | 28.0.0.0 借 12 位 → 4096 个子网 |
| **B** | N.N.H.H | 16 | **14** | 147.10.0.0 借 5 位 → 32 个子网 |
| **C** | N.N.N.H | 8 | **6** | 192.168.10.0 借 3 位 → 8 个子网 |

<Figure src="images/page_24.png" caption="Subnetting Class A and B：Class A 最多 22 位可借，Class B 最多 14 位" source="Slide 24" />

<Callout type="exam">

**为什么最多只能借到「host 位 − 2」**：至少要留 **2 位 host**，否则 2ʰ − 2 = 0（只剩 network address 和 broadcast address，没有可以给主机的地址）。留 2 位时每个子网 2² − 2 = **2 台主机**，正好够一条路由器之间的点对点线路（两端各一个接口）。Class C 同理最多借 6 位。

</Callout>

## 3. 🔴 Subnet Mask（子网掩码）

### 🔴 定义与求法（Slide 8–9）

- **Determines which part of an IP address is the network field and which part is the host field**
- 求法 4 步：① 把子网地址写成二进制 → ② **Network 和 Subnet 部分全写 1** → ③ **Host 部分全写 0** → ④ 换回点分十进制

<Figure src="images/page_09.png" caption="11111111.11111111.11110000.00000000：Class B 16 位 network + 4 位 subnet + 12 位 host → 255.255.240.0" source="Slide 9" />

**Default subnet mask**（不借位时）：

| Class | Default mask | /n |
|---|---|---|
| A | **255.0.0.0** | /8 |
| B | **255.255.0.0** | /16 |
| C | **255.255.255.0** | /24 |

### 🔴 一个 octet 里的掩码值（Slide 10）

<Figure src="images/page_10.png" caption="从左往右连续写 1：128、192、224、240、248、252、254、255" source="Slide 10" />

| 这个 octet 里借了几位 | 二进制 | 掩码值 | **子网间隔 = 256 − 掩码值** |
|---|---|---|---|
| 1 | 1000 0000 | **128** | 128 |
| 2 | 1100 0000 | **192** | 64 |
| 3 | 1110 0000 | **224** | 32 |
| 4 | 1111 0000 | **240** | 16 |
| 5 | 1111 1000 | **248** | 8 |
| 6 | 1111 1100 | **252** | 4 |
| 7 | 1111 1110 | **254** | 2 |
| 8 | 1111 1111 | **255** | 1 |

<Callout type="memo">

**128 · 192 · 224 · 240 · 248 · 252 · 254 · 255**：就是 128 + 64 + 32 + 16 + 8 + 4 + 2 + 1 从左往右**依次累加**。背下来之后，写掩码只要数「这个 octet 里借了几位」。

</Callout>

### 🔴 Slash format（Slide 11）

- **/n = 掩码里有 n 个 1** = Network 位 + Subnet 位
- 例：**/25 = 255.255.255.128**（Class C 借 1 位：24 + 1 = 25）；Slide 9 的 255.255.240.0 = **/20**（16 + 4）

<Callout type="board" title="老师板书 p.1：借 n 位 → 写 Subnet Mask（我的解答）">

**做法**：定 Class（看第一个 octet）→ 默认 N 位数 + 借的位数 = /n → 按 8 位一段写出掩码。

| # | 地址 | Class | 借 | /n | **Subnet mask** | 子网数 | 每子网主机 | 这个地址在的子网 |
|---|---|---|---|---|---|---|---|---|
| ① | 192.168.10.5 | C（24） | 3 | /27 | **255.255.255.224** | 8 | 30 | 192.168.10.0 |
| ② | 192.15.22.36 | C（24） | 4 | /28 | **255.255.255.240** | 16 | 14 | 192.15.22.32 |
| ③ | 130.12.108.5 | B（16） | 6 | /22 | **255.255.252.0** | 64 | 1,022 | 130.12.108.0 |
| ④ | 130.12.5.130 | B（16） | 10 | /26 | **255.255.255.192** | 1,024 | 62 | 130.12.5.128 |

- ③：借 6 位全在第 3 个 octet → 11111100 = **252** → 255.255.252.0
- ④：借 10 位 = 第 3 个 octet 借满 8 位（255）+ 第 4 个 octet 再借 2 位（11000000 = **192**）→ 255.255.255.192
- 最后一列用第 6 节的 AND 方法算：例如 ② 36 = 0010 0100，前 4 位 0010 是子网号 2 → 2 × 16 = **32**

</Callout>

## 4. 🔴 列出子网：Network · Host Range · Broadcast

### 🔴 借 1 位：2 个子网（Slide 13–14）

<Figure src="images/page_13.png" caption="192.168.1.0/24 借 1 位 → Subnet 0 = 192.168.1.0–127/25，Subnet 1 = 192.168.1.128–255/25，掩码都是 255.255.255.128" source="Slide 13" />

|---|---|---|

| Last host | 192.168.1.126 | 192.168.1.254 |

### 🔴 两个公式（Slide 15）

<Figure src="images/page_15.png" caption="Subnets = 2^n（n = bits borrowed）；Hosts = 2^n − 2（n = host bits remaining）：借 1 位 → 2 个子网；剩 7 位 → 128 个地址，126 台主机" source="Slide 15" />

| 算什么 | 公式 | n 是什么 |
|---|---|---|
| **子网数** | **2ⁿ** | **借了**几位 |
| **每个子网的主机数** | **2ʰ − 2** | **剩下**几位 host |

<Callout type="warn" title="踩坑提醒：一个减 2、一个不减">

- **子网数不减 2**：课件把全 0 的子网（Net 0）和全 1 的子网（Net 7）都拿来用了（Slide 17–18）
- **主机数要减 2**：每个子网里 host 全 0 = 这个子网的 network address，host 全 1 = broadcast address
- （课外：很老的教材会说子网数也要 −2，因为早期设备不支持 subnet zero。这门课按课件，**子网数 = 2ⁿ**。）

</Callout>

<Callout type="warn" title="课件笔误">

</Callout>

<Callout type="exam">

**列子网表的快捷方法（间隔法）**：
1. 找到借的位落在哪个 octet，看这个 octet 的掩码值（例如 224）
2. **间隔 = 256 − 224 = 32** → 子网地址就是 0、32、64、96、128、160、192、224
3. 每行：**Network = 这个数**；**Broadcast = 下一个子网 − 1**；**Host range = Network + 1 到 Broadcast − 1**

例：第 3 个子网 192.168.1.64 → broadcast 192.168.1.95 → 主机 .65–.94。不用写二进制也能很快算完；但考试写出「子网位 001、010…」那一列（像板书那样）更稳。

</Callout>

| … | … | … | … | … |
| 15 | 1111 | 192.15.22.240 | .241 – .254 | 192.15.22.255 |

板书 p.1 第 ② 题的 **192.15.22.36** 就在 **2 号子网**（.32 – .47）。

</Callout>

<Figure board src="images/BOARD4_TABLE_B6.png" caption="130.12.0.0 借 6 位：X.SSSSSS hh.H（X = 130.12），S.N # 0–5" source="M4 Supplementary p.5" />

<Callout type="board" title="老师板书 p.5：Class B 130.12.0.0 借 6 位（我的解答）">

X = 130.12；第 3 个 octet = **SSSSSS hh**，第 4 个 octet 全是 host（H）。掩码 **255.255.252.0（/22）**，2⁶ = **64 个子网**，每个 2¹⁰ − 2 = **1,022 台主机**。借的位在**第 3 个 octet**，间隔 = 256 − 252 = **4**（第 3 个 octet 每次 + 4）。

| S.N # | SSSSSS | Network address | Host Range | Broadcast |
|---|---|---|---|---|
| 0 | 000000 | 130.12.**0**.0 | 130.12.0.1 – 130.12.3.254 | 130.12.**3**.255 |
| 1 | 000001 | 130.12.**4**.0 | 130.12.4.1 – 130.12.7.254 | 130.12.**7**.255 |
| 2 | 000010 | 130.12.**8**.0 | 130.12.8.1 – 130.12.11.254 | 130.12.**11**.255 |
| 3 | 000011 | 130.12.**12**.0 | 130.12.12.1 – 130.12.15.254 | 130.12.**15**.255 |
| 4 | 000100 | 130.12.**16**.0 | 130.12.16.1 – 130.12.19.254 | 130.12.**19**.255 |
| 5 | 000101 | 130.12.**20**.0 | 130.12.20.1 – 130.12.23.254 | 130.12.**23**.255 |

注意 host 部分跨了两个 octet（hh.H = 2 + 8 = 10 位）：**network 是「第 3 段 hh = 00、第 4 段 = 0」**，broadcast 是「hh = 11、第 4 段 = 255」，所以 broadcast 的第 3 段是 network + 3。第一个主机 = .0.**1**，最后一个 = .3.**254**，中间像 130.12.1.0、130.12.2.255 这样的地址**都是合法的主机地址**。

</Callout>

<Figure board src="images/BOARD4_TABLE_B10.png" caption="130.12.0.0 借 10 位：X.SSSSSSSS.SS hhhhhh，S.N # 0–5" source="M4 Supplementary p.6" />

<Callout type="board" title="老师板书 p.6：130.12.0.0 借 10 位（我的解答）">

第 3 个 octet 全部借走（8 位）+ 第 4 个 octet 再借 2 位 → **SSSSSSSS.SS hhhhhh**。掩码 **255.255.255.192（/26）**，2¹⁰ = **1,024 个子网**，每个 2⁶ − 2 = **62 台主机**，间隔在**第 4 个 octet**：256 − 192 = **64**。

| S.N # | 子网位 | Network address | Host Range | Broadcast |
|---|---|---|---|---|
| 0 | 00000000.00 | 130.12.0.0 | .0.1 – .0.62 | 130.12.0.63 |
| 1 | 00000000.01 | 130.12.0.64 | .0.65 – .0.126 | 130.12.0.127 |
| 2 | 00000000.10 | 130.12.0.128 | .0.129 – .0.190 | 130.12.0.191 |
| 3 | 00000000.11 | 130.12.0.192 | .0.193 – .0.254 | 130.12.0.255 |
| 4 | 00000001.00 | 130.12.**1**.0 | .1.1 – .1.62 | 130.12.1.63 |
| 5 | 00000001.01 | 130.12.1.64 | .1.65 – .1.126 | 130.12.1.127 |

第 4 个 octet 用完 4 个子网（0、64、128、192）后，第 3 个 octet 进 1，从 130.12.1.0 再开始。板书 p.1 第 ④ 题的 130.12.5.130 在 **130.12.5.128/26**（子网号 5 × 4 + 2 = **22**）。

**p.5 和 p.6 对比**：同一个 130.12.0.0，借 6 位 → 64 个大子网（1,022 台）；借 10 位 → 1,024 个小子网（62 台）。**借得越多，子网越多、每个越小**——这就是第 5 节「按需求规划」要做的取舍。

</Callout>

## 5. 🔴 按需求规划：借几位？

### 🔴 两个考虑（Slide 20–22）

<Figure src="images/page_22.png" caption="Engineering 40 hosts、HR 20、Sales 20、Technical Support 20、Executive Management 15：按最大的子网设计，并留出增长空间" source="Slide 22" />

Two considerations when planning subnets（Slide 20）：
1. **Number of subnets required** → 决定**最少借几位**：2ⁿ ≥ 需要的子网数
2. **Number of host addresses required** → 决定**最少留几位 host**：2ʰ − 2 ≥ 每个子网需要的主机数

Slide 21–22 的原则：
- **Subnet needed for each department**（每个部门一个子网）
- **Balance the required number of subnets and hosts for the largest subnet**（按**最大**的那个子网算主机数）
- **Allow for growth in each subnet**（给每个子网留增长空间）

<Figure src="images/page_23.png" caption="Four Practice Problems：给出需要的子网数和主机数，求最少的 subnet bits 和 host bits；下面是 2⁰ 到 2¹⁵ 的对照表" source="Slide 23" />

| Problem | 需要子网 | 需要主机 | 最少 subnet 位 | 最少 host 位 | 为什么 |
|---|---|---|---|---|---|
| 1 | 200 | 200 | **8** | **8** | 2⁷ = 128 \< 200 ≤ 256 = 2⁸；2⁸ − 2 = 254 ≥ 200 |
| 2 | 5 | 15 | **3** | **5** | 2³ = 8 ≥ 5；2⁴ − 2 = 14 \< 15 ≤ 30 = 2⁵ − 2 |
| 3 | 12 | 3000 | **4** | **12** | 2⁴ = 16 ≥ 12；2¹² − 2 = 4094 ≥ 3000 |
| 4 | 100 | 100 | **7** | **7** | 2⁷ = 128 ≥ 100；2⁷ − 2 = 126 ≥ 100 |

<Callout type="warn" title="踩坑提醒：主机数别忘了 −2">

Problem 2 最容易错：15 台主机，2⁴ = 16 看起来够，但 **2⁴ − 2 = 14 不够**，要 5 位。**边界附近一定要减 2 再比较**。反过来，子网数不减 2（200 个子网用 2⁸ = 256，不是 2⁸ − 2）。

</Callout>

<SubnetPlanner />

<Figure board src="images/BOARD4_Q1.png" caption="① 200.1.1.0，Maximize the number of hosts per subnet：路由器 A 连 B、C、D，每台路由器下面有一个 LAN；# of subnets need、minimum # of bits to borrow、remain h bits、host range" source="M4 Supplementary p.7" />

<Callout type="board" title="老师板书 ①：200.1.1.0，让每个子网的主机尽量多（我的解答）">

**数网络**（上图）：A 的 LAN、B 的 LAN、C 的 LAN、D 的 LAN = 4 个；A–B、A–C、A–D 三条线 = 3 个 → **# of subnets need = 7**。

- 200 → Class C，host 有 8 位
- **Maximize hosts per subnet = 借得越少越好** → **minimum # of bits to borrow = 3**（2³ = 8 ≥ 7；2² = 4 不够）
- **Remain h bits** = 8 − 3 = **5** → 每个子网 2⁵ − 2 = **30** 台主机
- 掩码 **255.255.255.224（/27）**
- **Host range**：200.1.1.1–30、.33–62、.65–94、.97–126、.129–158、.161–190、.193–222（用 7 个），还剩一个 .224/27（.225–254）留作增长

**下图**（只有 A 连 B、C、D，没有画 LAN）：只要 A–B、A–C、A–D **3 个**子网 → 借 **2** 位（2² = 4 ≥ 3）→ 剩 6 位 → 每个 2⁶ − 2 = **62** 台，掩码 255.255.255.192（/26）。**网络越少，需要借的位越少，每个子网就越大。**

</Callout>

<Figure board src="images/BOARD4_Q2.png" caption="② 172.16.0.0：100 subnets，200 hosts per subnet；三行：minimum # of bits to borrow / # of subnets | remaining h bits / # of hosts per subnet" source="M4 Supplementary p.8" />

<Callout type="board" title="老师板书 ②：172.16.0.0，100 个子网、每个 200 台（我的解答）">

172 → Class B，host 有 **16** 位。

| | 借几位 | # of subnets | Remaining h bits | # of hosts per subnet | 满足吗 |
|---|---|---|---|---|---|
| 第 1 行 | **7**（minimum） | 2⁷ = **128** ≥ 100 ✓ | 16 − 7 = **9** | 2⁹ − 2 = **510** ≥ 200 ✓ | ✓ 主机最多 |
| 第 2 行 | **8** | 2⁸ = **256** ✓ | **8** | 2⁸ − 2 = **254** ✓ | ✓ 子网最多（/24） |
| 第 3 行 | **9** | 2⁹ = 512 ✓ | **7** | 2⁷ − 2 = **126** ✗ | ✗ 主机不够 |

**结论**：借 **7 或 8 位**都可以（掩码 255.255.254.0 或 255.255.255.0）。借 9 位时每个子网只有 126 台，**不满足 200 台**。三行对照正是老师想让我们看到的「子网数和主机数此消彼长」。

</Callout>

<Figure board src="images/BOARD4_Q34.png" caption="③ 178.13.0.0：40 subnets with 220 hosts、24 subnets with 90 hosts、15 subnets with 80 hosts；④ 192.5.12.0，S.N.M. =；192.5.12.135，224 borrow 3 bits，135 –" source="M4 Supplementary p.9" />

<Callout type="board" title="老师板书 ③：178.13.0.0，三种部门一起规划（我的解答）">

178 → Class B，16 位 host。

- **子网总数** = 40 + 24 + 15 = **79** → 最少借 **7** 位（2⁶ = 64 不够，2⁷ = 128 ≥ 79）
- **主机按最大的算**（Slide 22）= **220** → 最少留 **8** 位 host（2⁷ − 2 = 126 不够，2⁸ − 2 = 254 ≥ 220）→ 最多借 16 − 8 = **8** 位
- 可行：**借 7 位**（/23，255.255.254.0：128 个子网 × 510 台）或 **借 8 位**（/24，255.255.255.0：256 个子网 × 254 台）
- 两个都对；**借 8 位**更常见：掩码 255.255.255.0 好算，子网还剩 256 − 79 = 177 个可以给新部门。90、80 台的子网也用同样大小（固定长度子网，每个都浪费一些地址）

</Callout>

<Callout type="extra" title="课外补充：VLSM（可变长子网掩码）">

第 ③ 题里 90 台和 80 台的部门也分到了能放 254 台的子网，浪费了不少地址。**VLSM (Variable Length Subnet Mask)** 允许不同子网用不同的掩码：220 台用 /24，90 和 80 台用 /25（126 台），路由器之间的线路用 /30（2 台）。课件用的都是**同一个掩码**（Slide 13：*2 subnets with the same subnet mask*），考试按课件做即可。今天 Internet 上用的 **CIDR** 也是同样的思路，彻底抛弃了 Class A/B/C 的固定边界。

</Callout>

## 6. 🔴 ANDing：一个地址属于哪个子网？

<Figure src="images/page_25.png" caption="197.15.22.131，掩码 255.255.255.224（借 3 位）：最后一个 octet 100 | 00011 → 在子网 197.15.22.128" source="Slide 25" />

<Figure src="images/page_26.png" caption="ANDing：192.168.10.65 AND 255.255.255.224 = 192.168.10.64" source="Slide 26" />

- **ANDing is a binary process by which the router calculates the subnetwork ID for an incoming packet**
- **1 AND 1 = 1；1 AND 0 = 0；0 AND 0 = 0**
- **The router then uses that information to forward the packet across the correct interface**（算出子网地址 → 查路由表）

| | 十进制 | 最后一个 octet（二进制） |
|---|---|---|
| Packet address | 192.168.10.**65** | **010** 00001 |
| Subnet mask | 255.255.255.**224** | **111** 00000 |
| **AND 结果** | 192.168.10.**64** | **010** 00000 |

<Callout type="tip">

**AND 的直觉**：掩码是 1 的位 → 地址**原样保留**（network + subnet 部分）；掩码是 0 的位 → **全部清零**（host 部分）。结果就是「把 host 位全变成 0」——正是这个子网的 **network address**。所以心算时直接用间隔法：65 落在 64–95 这一段 → 子网 64。

</Callout>

<Figure src="images/page_27.png" caption="172.16.2.120 AND 255.255.255.0 (/24) = 172.16.2.0：Class B 借了 8 位（Eight bits of subnetting）；主机范围 172.16.2.1–254，broadcast 172.16.2.255" source="Slide 27" />

<Callout type="exam">

Slide 27 的陷阱：**255.255.255.0 不一定是「Class C 的默认掩码」**。172.16.2.120 是 **Class B**（默认 /16），用 /24 表示**借了 8 位**做子网（Eight bits of subnetting），所以 172.16.**2**.0 是第 2 个子网。**先看 Class，再看掩码比默认多了几位**。

</Callout>

<Callout type="board" title="老师板书 ④：192.5.12.0，S.N.M. = ?，192.5.12.135 在哪个子网（我的解答）">

板书写着 **224 → borrow 3 bits**：

- **S.N.M. (Subnet mask) = 255.255.255.224（/27）**，8 个子网 × 30 台，间隔 32
- **192.5.12.135**：135 = **100** 00111
  - AND 11100000 → **100** 00000 = **128**
  - 子网号 100 = **4** → Network address **192.5.12.128**
  - Broadcast = 128 + 31 = **192.5.12.159**，Host range **192.5.12.129 – 192.5.12.158**
  - 135 是普通主机地址（不是 128，也不是 159）
- 和 Slide 25 的 197.15.22.131 → .128 是同一类题

</Callout>

## 7. 🔴 做题总流程（把整周串起来）

| 步 | 做什么 | 例：130.12.108.5 借 6 位 |
|---|---|---|
| 1 | 看第一个 octet 定 **Class** → 默认 N 位数 | 130 → B → 16 位 |
| 2 | **N + S** = /n，写出**掩码** | 16 + 6 = /22 → 255.255.**252**.0 |
| 3 | **子网数 2ⁿ**、**每子网主机 2ʰ − 2** | 2⁶ = 64；h = 10 → 1,022 |
| 4 | 找借位所在的 octet，**间隔 = 256 − 掩码值** | 第 3 段，256 − 252 = 4 |
| 5 | 列子网：Network（这个数）→ Broadcast（下一个 − 1）→ Host range | 130.12.0.0 – 130.12.3.255，130.12.4.0 – … |
| 6 | 找某个地址的子网：**AND**（或看落在哪个区间） | 108 ÷ 4 = 27 → 130.12.108.0，broadcast 130.12.111.255 |

## 9. 模拟自测题

> 以下是**自测题**，按本笔记顺序排列，用来检查自己是否真的掌握，**不是预测的考题**。点开看参考答案。

<QA q="1. 为什么要把一个大网络划分成子网？至少说出三点。">

① 把广播限制在每个子网内部（control broadcast traffic）；② 减少整体流量、提高性能；③ 不同子网之间要经过路由器，可以用 ACL 等控制访问（例如把考试服务器和学生 PC 分开），便于管理和安全隔离。另外对外仍然是一个网络，Internet 路由表只需一条。

</QA>

<QA q="2. 「借位」是从哪里借？N、S、H 三部分的位数有什么关系？">

从原来 host 部分的**最左边**开始连续借，借来的位叫 subnet field。N + S + H = 32。

</QA>

<QA q="3. 写出 Class A、B、C 的默认掩码，以及最多能借几位。">

A：255.0.0.0（/8），最多借 22 位；B：255.255.0.0（/16），最多借 14 位；C：255.255.255.0（/24），最多借 6 位。都要留至少 2 位 host。

</QA>

<QA q="4. 一个 octet 里借 5 位，这个 octet 的掩码值是多少？子网间隔是多少？">

11111000 = 128 + 64 + 32 + 16 + 8 = **248**；间隔 = 256 − 248 = **8**。

</QA>

<QA q="5. 172.20.0.0 借 5 位：写出掩码（点分和斜杠）、子网数和每个子网的主机数。">

Class B，16 + 5 = **/21** → 第 3 个 octet 11111000 = 248 → **255.255.248.0**；子网 2⁵ = **32** 个；host 位 = 11 → 2¹¹ − 2 = **2,046** 台。

</QA>

<QA q="6. 192.168.5.0 借 2 位，列出 4 个子网的 network、host range 和 broadcast。">

掩码 255.255.255.192，间隔 64：
.0（.1–.62，bc .63）；.64（.65–.126，bc .127）；.128（.129–.190，bc .191）；.192（.193–.254，bc .255）。

</QA>

<QA q="7. 为什么子网数用 2ⁿ，主机数却用 2ʰ − 2？">

每个子网里 host 全 0 是这个子网的 network address，host 全 1 是它的 broadcast address，都不能分配给主机，所以减 2。子网号本身没有这个限制，课件把全 0 和全 1 的子网（Net 0、Net 7）都用上了。

</QA>

<QA q="8. 一家公司拿到 Class C 网络，需要 6 个子网，每个子网最多 25 台主机。借几位？掩码是多少？每个子网实际能放几台？">

6 个子网 → 借 3 位（2³ = 8）；剩 5 位 → 2⁵ − 2 = 30 ≥ 25 ✓。掩码 **255.255.255.224（/27）**，每个子网 **30** 台。

</QA>

<QA q="9. 需要 5 个子网、每个 15 台主机（Slide 23 Problem 2），为什么 host 要 5 位而不是 4 位？">

4 位 host：2⁴ − 2 = 14 \< 15，不够；5 位：2⁵ − 2 = 30 ≥ 15。子网 3 位（2³ = 8 ≥ 5），3 + 5 = 8 位，正好是一个 Class C 的 host 部分。

</QA>

<QA q="10. 172.16.0.0 需要 100 个子网、每个 200 台主机。可以借几位？借 9 位为什么不行？">

最少借 7 位（2⁷ = 128 ≥ 100）；每个子网要 200 台 → 至少 8 位 host → 最多借 16 − 8 = 8 位。所以借 **7 或 8 位**。借 9 位只剩 7 位 host，2⁷ − 2 = 126 \< 200。

</QA>

<QA q="11. 路由器 A 连着 B、C、D 三台路由器，每台路由器（包括 A）各有一个 LAN，用 200.1.1.0，要让每个子网主机最多。借几位？每个子网几台？">

网络数 = 4 个 LAN + 3 条路由器之间的线 = 7 → 最少借 3 位（2³ = 8）。要主机最多就借最少的位 → 借 3 位，剩 5 位 → **30** 台，掩码 255.255.255.224。

</QA>

<QA q="12. 用 AND 求 10.1.77.200/255.255.240.0 所在的子网地址和广播地址。">

Class A，/20。第 3 个 octet：77 = 0100 1101，AND 1111 0000 = 0100 0000 = **64** → 子网 **10.1.64.0**；间隔 16 → 下一个子网 10.1.80.0 → broadcast **10.1.79.255**。

</QA>

<QA q="13. 192.5.12.135，掩码 255.255.255.224：network address、broadcast address、host range 分别是？它是第几个子网？">

135 = 100 00111 → 子网位 100 = **第 4 个**（从 0 数）。Network **192.5.12.128**，broadcast **192.5.12.159**，host range **.129 – .158**。

</QA>

<QA q="14. 172.16.2.120 的掩码是 255.255.255.0，借了几位？为什么不是「默认掩码」？">

172 是 Class B，默认 /16；/24 比默认多 8 位，所以**借了 8 位**做子网（Slide 27：Eight bits of subnetting），子网地址 172.16.2.0。255.255.255.0 只有对 Class C 才是默认掩码。

</QA>

<QA q="15. 130.12.0.0 借 6 位和借 10 位各有什么优缺点？">

借 6 位（/22）：64 个子网 × 1,022 台，子网少但大，适合部门少、每个部门人多；借 10 位（/26）：1,024 个子网 × 62 台，子网多但小，适合部门多、每个人少。借得越多，子网越多、每个子网越小。

</QA>
